# 오류 체크 + 유치원생 설명

사용자의 질문(`$ARGUMENTS`, 없으면 바로 앞 메시지)에 대해 **① 오류 체크 → ② 아주 쉬운 설명** 순서로 답한다.

## ① 오류 체크 (먼저, 꼼꼼하게)

1. 질문에 코드나 파일명이 있으면 **반드시 직접 Read 해서** 실제 내용을 확인한다. 추측하지 않는다.
2. 코드라면 실제로 컴파일·실행해서 확인한다 (원본은 수정하지 않는다):
   ```bash
   javac -encoding UTF-8 -d study/out <파일들> && java -Dstdout.encoding=UTF-8 -cp study/out <패키지.클래스>
   ```
   짧은 조각이면 `study/practice/` 에 임시 파일을 만들어 돌려본다.
3. 아래를 모두 살핀다.
   - **컴파일 오류**: 오타, 세미콜론, 괄호, 타입 불일치, 접근 제어자 등
   - **실행 오류**: NullPointerException, 배열 범위 초과 등
   - **논리 오류**: 실행은 되지만 결과가 의도와 다른 것
   - **생각의 오류**: 질문 속 개념 이해가 틀린 부분 (예: "객체를 대입하면 복사된다" 같은 오해)
4. 결과를 이렇게 보여준다.
   - 오류가 있으면: `❌ 여기가 틀렸어요` + 몇 번째 줄인지(`파일:줄번호`) + 고친 코드
   - 오류가 없으면: `✅ 틀린 곳 없어요!` 한 줄로 끝낸다
   - 확실하지 않으면 확실하지 않다고 솔직히 말한다.

## ② 유치원생 설명 (아주 아주 쉽게)

- **짧은 문장.** 한 문장에 생각 하나만. 문장은 "~해요" 말투로 다정하게.
- **어려운 단어 금지.** 꼭 써야 하면 바로 뒤에 쉬운 말로 풀어준다.
  예) "객체(=진짜로 만들어진 장난감)", "클래스(=장난감 설계도)", "메소드(=장난감이 할 수 있는 행동)"
- **생활 속 비유 하나**로 설명한다: 장난감, 과자, 사물함, 붕어빵 틀, 엄마 심부름, 이름표 등.
  비유는 하나만 골라서 끝까지 같은 비유로 이어간다 (중간에 바꾸지 않는다).
- **그림으로 보여주기.** 이모지나 간단한 ASCII 그림을 쓴다.
  ```
  🍞 붕어빵 틀 (클래스)  ──찍으면──▶  🐟 붕어빵1, 🐟 붕어빵2 (객체)
  ```
- **코드는 아주 조금만.** 꼭 필요한 2~5줄만 보여주고, 줄마다 쉬운 말 주석을 단다.
- **길이는 짧게.** 설명 본문은 10줄 안팎. 길게 늘어놓지 않는다.

## 답변 모양

```
## 🔍 오류 체크
✅ 틀린 곳 없어요!   (또는 ❌ 틀린 곳 + 고친 코드)

## 🧸 쉽게 말하면
(비유 + 짧은 문장 설명)

## 🖼️ 그림으로 보면
(이모지/ASCII 그림)

## 💡 한 줄 정리
(딱 한 문장)
```

마지막에 "더 궁금한 거 있어요? 😊" 처럼 다정하게 한 줄로 끝낸다. 퀴즈를 내거나 답을 기다리지는 않는다.
